How should someone link Telegram to a shop?

Guided POS still needs a trusted identity. This is the biggest security decision. Click one model.

A

Dashboard starts the link (current model)

Owner/manager is already signed in → Settings → Link Telegram → open bot → Start. Bot never invents access. Hard to phish. Extra step: must use the web dashboard first.

Bot can still feel polished: /start without token shows “Open Settings → Telegram” + help.

B

Pairing code either direction (recommended)

From dashboard: show a 6-digit code (or deep link) → user types code in bot, or opens link.
From bot: /link → bot shows a short code → user enters it in dashboard “Enter bot code”.

Feels “connect from the bot” without letting strangers claim shops. Codes expire, one-time, bound to logged-in staff.

C

Owner invites staff with bot deep links

Dashboard generates invite links for specific people/roles. Staff only open the link in Telegram. No reverse “bot → claim shop” flow. Great for multi-staff; still dashboard-originated.

D

Phone match + OTP (heavier)

Bot asks for phone (Share contact). Platform matches membership phone / sends OTP to dashboard or SMS. Nice for Ethiopia if phones are trusted identity — more product + ops surface.

What we keep either way

  • Operator binding ≠ notification destination
  • Only owner/manager (or invited roles) get write tools
  • Fail closed on callbacks

Avoid

  • “Type your shop name” to claim access
  • Anyone who messaged the bot becomes admin
  • Shared group chat as the operator identity

Lean: B — bidirectional pairing codes. Bot feels self-serve; security still starts from a logged-in dashboard user.
